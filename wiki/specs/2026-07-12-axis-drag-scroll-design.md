# 레이어 심도 드래그 스크롤 네비게이션 — 설계

날짜: 2026-07-12
관련: [[architecture]], [[core-decisions]] (wiki)

## 배경 / 문제

현재 `AxisGizmo.gd`는 X/Y/Z 화살표를 **탭할 때마다** depth를 1칸씩 순환한다
(`on_axis_tapped`: -1 → 0 → 1 → … → size-1 → -1). 큐브가 클수록(4×4×4, 향후 5×5×5)
원하는 층까지 여러 번 탭해야 해서 조작이 번거롭다는 피드백.

또한 `AxisGizmo._depths` 배열이 축별로 독립적으로 depth를 기억하는 반면,
`BlockGrid.set_depth_filter`는 단일 `_filter_axis`/`_filter_depth`만 유지한다.
즉 렌더링은 이미 "한 번에 한 축만" 필터링되고 있었지만, 제스처 계층은 그 제약을
명시적으로 반영하지 않았다. 이번 설계에서 이 제약을 인터랙션 레벨까지 끌어올린다.

## 목표

- 화살표를 잡고 드래그하면 그 축 방향으로 레이어가 스크롤되듯 이동
- 한 축이 활성화된 동안 다른 두 축은 조작 불가(시각적으로도 숨김)
- 리셋 수단 제공 — 전체 보기(depth=-1)로 즉시 복귀

## 비목표

- ○/□ 힌트 마커 (별도 백로그, wiki 결정 사항으로만 기록)
- 레이어 슬라이더 UI(별도 게임-디자인 "열린 질문" 항목, 이번 스코프 아님)
- 여러 축 동시 필터링 (현재도 미지원, 이번에도 도입 안 함)

## 인터랙션 설계

### 제스처: 드래그 전용

화살표는 탭-사이클 대신 드래그 전용으로 동작한다. 탭 동작(순간 터치+해제, 이동
없음)은 아무 효과도 없다 — 최소 이동량 이상 움직여야 depth가 바뀐다.

### 축 잠금 상태 기계

```
[대기: 3축 모두 표시, depth=-1]
   ↓ 화살표 A 터치다운 (레이캐스트로 감지)
[A 활성: 나머지 두 화살표 visible=false, 리셋 버튼 활성화]
   ↓ 드래그 → depth 증감
   ↓ 손 뗌 → depth 값 유지, A 계속 활성 (다시 잡고 이어서 스크롤 가능)
   ↓ 리셋 버튼 탭
[대기 상태로 복귀: depth=-1, 3축 모두 다시 표시, 리셋 버튼 비활성화]
```

다른 축 화살표가 터치다운 시점에 이미 숨겨져 있으므로(레이캐스트 대상이 아님),
"A 활성 중 B를 만질 수 없다"는 자연히 보장된다 — 별도의 잠금 플래그 검사 불필요.

### 픽셀→레이어 변환

- 화살표의 **현재 화면상 2D 투영 방향 벡터**(카메라가 매 프레임 바뀌므로 매번 재계산)에
  프레임별 드래그 델타를 내적해 부호 있는 스칼라로 누적한다.
- 누적값이 `STEP_PIXELS`(기본 60px, 상수로 분리) 이상/이하가 될 때마다 depth ±1,
  초과분은 다음 스텝으로 이월(연속 드래그가 끊기지 않게).
- depth는 `[0, size-1]`로 클램프 — 경계에서는 더 끌어도 멈춘 상태 유지.
- 손을 뗐다가 같은 화살표를 다시 잡으면 누적 스칼라는 0부터 다시 시작(직전
  이월분은 버림) — 매 드래그 시퀀스가 예측 가능하게 시작하도록.

### 컴포넌트별 변경

**`AxisGizmo.gd`**
- 제거: `on_axis_tapped(axis)`
- 추가:
  - `begin_drag(axis: int) -> void` — 화살표 터치다운. 다른 화살표가 숨겨진 상태(=이미
    한 축 활성 중)라면 이 축에 대한 새 `begin_drag` 호출 자체가 들어올 수 없음(레이캐스트가
    숨은 콜라이더를 못 잡음 — `collision_layer`도 함께 꺼서 이중 보장).
  - `update_drag(screen_delta: Vector2) -> void` — 프레임마다 누적, 임계값 넘으면
    `depth_changed(axis, new_depth)` emit.
  - `end_drag() -> void` — 누적 스칼라 초기화. depth/활성 축 상태는 유지.
  - `reset() -> void` — depth=-1로, 모든 화살표 다시 표시, `depth_changed(axis, -1)` emit.
  - `_screen_direction(axis: int) -> Vector2` — 카메라 `unproject_position`으로 화살표
    시작점/끝점을 화면 좌표로 변환해 방향 벡터 계산 (내부 헬퍼, 순수 함수로 분리해 테스트 가능하게).
  - `_accumulate(axis: int, delta_scalar: float) -> int` — 누적값 → depth 변화량 계산
    (스텝 카운트, 이월 처리). 노드 상태 없이 입력→출력만으로 테스트 가능한 순수 함수로 분리.

**`CameraController.gd`**
- 터치다운(`_on_touch`, index==0, pressed) 시점에 레이캐스트를 먼저 수행해 화살표
  히트 여부 판정. 히트하면 이후 같은 터치 인덱스의 `_on_drag` 이벤트를 오빗 회전이
  아니라 `AxisGizmo.begin_drag`/`update_drag`로 라우팅. 히트 안 하면 기존 오빗 로직 그대로.
- 핀치 줌(2손가락)은 축 드래그와 별개 — 축 드래그 중 두 번째 손가락이 닿아도 핀치로
  전환하지 않음(축 스크롤이 우선권을 가짐, 손 하나 더 놓는 실수로 줌 안 되게).

**`HUD.gd`**
- 리셋 아이콘 버튼(↻) 추가, 기존 기어/일시정지 버튼 옆. 기본 `disabled = true`.
- `signal reset_pressed`

**`Main.gd`**
- `_gizmo.depth_changed` 연결은 유지(콜백 시그니처 동일).
- `_hud.reset_pressed.connect(_gizmo.reset)` 배선.
- 축 활성/비활성 전환 시 HUD 리셋 버튼 `disabled` 상태 갱신 — `AxisGizmo`에
  `signal axis_lock_changed(is_locked: bool)` 추가해 `Main.gd`가 구독.

## 에러 처리 / 엣지 케이스

- 드래그 도중 손가락이 화면 밖으로 나가거나 앱이 백그라운드로 전환 → 표준 터치 해제
  이벤트로 `end_drag()`가 호출되는 한 자연히 처리됨(별도 타임아웃 불필요).
- size=1인 축(이론상 없음, 최소 3) 고려 불필요.
- depth가 이미 경계값일 때 같은 방향으로 계속 드래그 → 누적값이 계속 쌓이지 않도록
  경계에 닿으면 누적 스칼라를 0으로 리셋(반대 방향으로 살짝만 되돌려도 바로 반응하게).

## 테스트 범위

- `_accumulate(axis, delta_scalar)`류 순수 함수는 `tests/`에 GDScript 헤드리스 유닛
  테스트 추가 (기존 `test_puzzle_model.gd` 패턴 재사용 — 새 `test_axis_gizmo.gd` 또는
  기존 파일에 케이스 추가, 구현 단계에서 결정).
- 나머지(레이캐스트 라우팅, 화면 투영, 락 상태에 따른 visible 토글)는 노드/카메라 의존이라
  에디터 수동 QA로 검증 — 6단계 코드(`CameraController` 분기)가 오빗 회전을 깨지 않는지가
  핵심 회귀 포인트.

## 백로그 (이번 스코프 아님, 결정만 기록)

  ○/□ 마커를 추가로 표시한다(런 길이 자체는 알려주지 않음). 이 프로젝트도 처음부터
  같은 방식(총 개수만)을 채택했고 마커는 프로토타입에서 제외하기로 2026-06-23에 이미
  결정된 바 있음. 2026-07-12 재확인 — 이번 작업(레이어 네비)에 집중하기 위해 계속 백로그로 둠.
